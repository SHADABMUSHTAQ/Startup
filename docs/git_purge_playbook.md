# Git History Purge Playbook — Remove `private_key.pem`

WARNING: These steps rewrite repository history. Do NOT run them without coordination, backups, and a communications plan.

This playbook shows the exact safe steps to remove `private_key.pem` from the entire Git history using `git-filter-repo`. These commands are to be run locally by an authorized operator. The agent will not execute any destructive commands.

Prerequisites
- A machine with Git and Python 3 installed.
- Access to the repository remote (read+write) and permission to force-push.
- Enough disk space for a full mirror copy of the repo.
- Team coordination and a maintenance window.

High-level plan
1. Create a bare mirrored backup of the repository. Keep this offline and immutable.
2. Run `git-filter-repo` on the mirrored copy to remove the exact path(s).
3. Verify the private file is gone from the mirror.
4. Notify the team and force-push the cleaned refs to the remote.
5. Rotate any credentials that were exposed and require key-rotation in deployed systems.
6. Instruct all collaborators to re-clone the repository.

Step-by-step (exact commands)

1) Create an immutable mirror backup (do this first)

```bash
# From a safe working directory (outside the repo), clone a mirror
git clone --mirror <REPO_URL> repo-mirror.git

# OR from the repo root (create a mirror of the local repository)
# cd /path/to/your/repo
# git clone --mirror . ../repo-mirror.git
```

Keep `repo-mirror.git` safe. This is your rollback copy.

2) Install `git-filter-repo` (if not present)

```bash
# python/pip method (recommended):
python3 -m pip install --user git-filter-repo

# On Windows you can use the same pip install command with your Python
```

3) Run the filter on the mirror (DRY-RUN mental checklist first)

Important: Replace the path(s) exactly as stored in Git. Examples below assume the file was `keys/private_key.pem` or `private_key.pem` at repo root.

```bash
cd repo-mirror.git

# Remove a single path from history (recommended safe syntax)
# This rewrites history in the mirror copy only.
git filter-repo --path private_key.pem --invert-paths

# If the file was at keys/private_key.pem use:
# git filter-repo --path keys/private_key.pem --invert-paths
```

Notes:
- `--invert-paths` instructs `git-filter-repo` to remove the specified path(s) from history.
- Test on the mirror first. Do not run this in your active working clone.

4) Verify the file has been removed from the mirror

```bash
# Search the rewritten mirror for remaining references (should return nothing)
git rev-list --all | xargs -n1 git grep -F "private_key.pem" || true

# Also inspect the latest commits and tree to ensure content is gone
git log --all --name-only | grep private_key.pem || true
```

5) Push the cleaned history back to the remote (team coordination required)

Before pushing, communicate with the team and ensure everyone has a backup. Once pushed, everyone must re-clone.

```bash
# Add remote if needed and force-push all refs (tags included)
git remote add origin-clean <REPO_URL>
git push --force origin-clean --all
git push --force origin-clean --tags
```

6) Post-purge operations (critical)

- Rotate the RSA keys used for signing (we have already generated new keys locally).
- Rotate any credentials that may be derived from the purged key.
- Ensure all deployment pipelines use the rotated keys/secrets.
- Instruct every collaborator to delete their local clones and re-clone from the cleaned remote.

7) Rollback plan

- If anything goes wrong, you have the `repo-mirror.git` backup. Do NOT overwrite that backup.
- Restore from `repo-mirror.git` and re-run steps after diagnosing the issue.

Verification checklist (run after pushing)
- No `private_key.pem` in `git log --all --name-only` output.
- CI pipelines run against a fresh clone and pass.
- Production systems use rotated keys; signature verification succeeds with the new public keys.

Security notes
- This operation is disruptive. Force-pushing rewritten history invalidates commit SHAs. Coordinate releases, PRs, and CI jobs.
